    Join us¶

    You can help test how models use rules supplied in a prompt, or whether skills learned with numbers transfer to text, logic, and sound. The experiment ideas report designs without training results. The Worlds show example starting operations; you can add rules from a field you know.

    Ways to take part¶

    Share an idea¶

    Propose an experiment, or tell us which existing idea you most want to see run, and why; the reason often helps more than the vote.

    Discussions

    Run an experiment¶

    Pick a design from the experiment ideas, run it, and post what you saw. Post a result with no gain too, so the next person knows that path has been tried.

    Discussions

    Build a world¶

    Register atoms from chemistry, music theory, a game or your own work, then contribute them as a starting set with a config, or as a plugin module.

    Atoms guide

    Report a problem¶

    A crash, a wrong answer, or a derivation step the checker accepted and you think it should not have. Paste the command and the seed if you have them.

    Issues

    Improve the docs¶

    Fix a sentence that confused you, add the example you wished a page had, or offer a translation into a language you read well.

    Issues

    Add an integration¶

    Connect Opulse to a trainer, an evaluation harness or an interpretability tool, so the data and the step checker reach the tools people already use.

    Contributing guide

    Cite and tell others¶

    If Opulse helps your work, cite it. If you know someone who studies these questions, send them the link.

    Citation

    How we work together¶

    • Use Discussions for ideas and questions. Use Issues for reproducible problems.
    • The GitHub contributors page lists code contributors. Include attribution when an experiment builds on someone else's idea.
    • A typo fix, a failed command with reproduction steps, or a clearer example can improve the docs.
    • If an experiment cannot answer its question, explain which comparison or measurement is missing.

    The technical steps (setup, tests, code style, pull requests and licences) are in CONTRIBUTING.md. Everyone who takes part follows the code of conduct.

    Good first steps¶

    1. Install Opulse and run the tests:

      git clone https://github.com/mkj69/opulse.git && cd opulse
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python -m pytest -q
python tools/sweep.py --quick   # the pipeline under 11 settings, about 16 s

    2. Write a definition of your own in the playground and step through its evaluation. Nothing to install for this one.

    3. Read the experiment ideas and pick the one you would most like to know the answer to. Then say so in Discussions.

    Cite¶

    To cite Opulse, use the citation file in the repository (CITATION.cff) or the entry at the end of the blog post.
