    Tree

    opulse.trace.tree ¶

    Hierarchical derivations: one derivation that can be read at any granularity.

    A :class:Derivation is the reduction of one expression in which every defined operator is computed in one step (an eval step). Each such step carries a child: the derivation of that application on its own, op(inputs), which unfolds op once (an expand or undefined step) and computes the applications of the body, each defined one again in one step with a child of its own. Following children all the way down reaches base operations only.

    The cut (which defined operators are known) only decides how much of the tree is shown. :func:flatten replaces every eval step of an operator that should be unfolded by the steps of its child, recursively, and gives exactly the :class:~opulse.trace.Trace that :class:~opulse.trace.Reducer produces with the same expand and max_depth (tests/test_trace_tree.py checks this). The reduction is applicative order, leftmost-innermost, so the body of an unfolded application is reduced completely before anything to its right, which is what makes the splice exact.

    Every node is a reducer trace of its own and is checked with :func:opulse.verify.verify_trace (:func:verify_tree).

    JSON (:func:to_json, schema opulse.derivation/1)::

    {
  "schema": "opulse.derivation/1",
  "expression": "<text of the expression>",
  "value": <int> | null,            # null: undefined (NaN)
  "root": "<node id>",
  "operators": {"<func_id>": {"symbol", "n_ary", "position", "layer", "kind",
                              "priority", "associativity", "definition"}},
  "nodes": {"<node id>": {
      "operator": "<func_id>" | null,   # null for the root expression
      "inputs": [<int> | null, ...],     # null: NaN; [] for the root
      "source": <tree>, "text": "<text of source>", "value": <int> | null,
      "steps": [{"kind": "expand" | "eval" | "undefined",
                 "path": [<child index>, ...],   # from the node's source
                 "operator": "<func_id>", "inputs": [...], "depth": <int>,
                 "before": <tree>, "after": <tree>, "expression_after": <tree>,
                 "branch": <int> | null, "condition": "<text>" | null,
                 "reason": "nan_condition" | "no_branch" | null,
                 "child": "<node id>" | null}]}}
}

    kind of an operator is base (no definition), simple, branch or recursive. A <tree> is {"num": <int>}, {"num": null} (NaN), {"var": "<name>"} or {"op": "<func_id>", "args": [<tree>, ...]}. Node ids are n0 (the root), n1, ... in the order the nodes were built; equal applications share one node. depth is local to the node: 0 for steps on the node's own source, 1 for the body of its unfolding.

    cut ¶

    cut(
    known: Iterable[str] = (), known_layers: int = 0
) -> Callable[[Operator], bool]

    The expand predicate of a cut, as in opulse expressions --cot-known(-layers).

    A defined operator is unfolded unless its layer is below known_layers or its symbol or func_id is in known.

    flatten_view(
    root: Derivation,

) -> list[ViewStep]

    The steps of root at a cut, with the node behind every remaining defined eval.

    align ¶

    align(
    root: Derivation,
    expands: list[Callable[[Operator], bool]],
) -> tuple[list[list[ViewStep]], list[tuple[int, ...]]]

    The derivation at several cuts, ordered from coarse to fine, and how their steps line up.

    Returns (views, owners): views[k] is :func:flatten_view at expands[k], and owners[j][k] is the index of the step at cut k that the j-th step at the finest cut belongs to (so owners[j][-1] == j). One step at a coarser cut stands for a contiguous block of finer steps. Every cut must unfold at least what the cut before it unfolds; otherwise a ValueError is raised.
