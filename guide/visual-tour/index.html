    Visual tour¶

    Each widget shows a different way to use generated rules. An atom is an operation computed directly; an operator is a named operation built from atoms or other operators. The examples use fixed seeds and sets of about 10, 100, 1,000, and 10,000 operators. Shapes such as ◆₁ are names, not clues to a rule (notation).

    Grow an operator set¶

    See how operators build on earlier ones across layers. Choose a scale, then select an operator to see its definition and the rules it needs.

    Operator sets grown with fixed seeds at four sizes.

    One measured run with reduced acceptance checks grew 100,000 operators in about 8.1 hours (Performance).

    Unfold to atoms at any granularity¶

    An unfolding replaces a defined call with the branch selected by its inputs. An atom computes its result directly. Granularity sets how much work each step shows: with all operators known, a computation may take one step; fully unfolded, it may take tens of thousands. Choose a layer boundary or mark known operators in the searchable groups, then compare the step count for the same answer. The Steps view shows 50 steps per page and lets you jump to any step; the Tree view loads branches when opened.

    Test a model in context¶

    The same question gets a different answer when one supplied definition changes. Choose a pair and step through both answers to see where they diverge.

    You are given operators defined from a few base operations. Use the rules and the definitions exactly as written; do not assume any familiar meaning of the symbols.
Rules:
Values are integers or NaN (undefined).
Base operations:
  - a - b is integer subtraction.
  - a * b is integer multiplication.
  - a % b is the remainder a - b * (a / b), with the sign of a (-7 % 2 = -1); b = 0 gives NaN.
  - a $ is the number of 1 bits in the binary form of |a| (7 $ = 3).
  - & a is sign(a) times the sum of the decimal digits of |a| (& -123 = -6).
Any base operation whose result is larger than 2147483647 in absolute value gives NaN.
A base operation with a NaN argument gives NaN.
A definition `lhs = { e1, if c1; e2, if c2; ...; e, else }` tries its branches in order and returns the first branch whose condition holds; `else` always holds.
If no branch holds, the result is NaN. If a compared value is NaN, the result is NaN.
Unary operators bind tighter than binary ones; a postfix operator binds tighter than a prefix one.
A binary operation used inside another binary operation is always written in parentheses.
Definitions:
■₁ a = { a * a }
a ♦₃ = { ((& a) $) % ((■₁ a) $) }
What is the value of `61 ♦₃`?
Reason step by step if you wish, then finish with a line of the form "Answer: <integer or NaN>".
reference answer: 3
with
  a ♦₃ = { (& (■₁ a)) - (■₁ (& a)) }
instead of
  a ♦₃ = { ((& a) $) % ((■₁ a) $) }
the reference answer is -36

    Prove or refute an equivalence¶

    Each pair may agree everywhere or have a counterexample. Step through the pairs and inspect whether z3 proved a claim or the interpreter checked the stated range.

    Inlining (z3 proof): ■₁ a  ==  a * a  ->  proved
Constant folding (z3 proof): (a + 0) * (2 + 3)  ==  a * 5  ->  proved
Disjoint branches (z3 proof): a ⊕ b  ==  a ⊗ b  ->  proved
Bounded recursion (exhaustive on [0, 8]): ◈ a  ==  a  ->  checked
Rare interior input (interpreter checked counterexample): a ⊛ b  ==  a + b  ->  refuted  counterexample {'a': 2, 'b': -3}: 0 vs -1
Value bound (interpreter checked counterexample): (a + b) - b  ==  a  ->  refuted  counterexample {'a': 1, 'b': 2147483647}: None vs 1
